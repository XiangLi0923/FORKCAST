# 答辩题库与证据

回答顺序可用「一句结论、一个机制、一个证据」。未做的事情直接说状态。

| 评委问题 | 可直接回答 | 可指证据 |
| --- | --- | --- |
| 为什么是午餐？ | 校园午餐高频、时间短、供给会变，可以用同一个场景测选择成本和供给反馈。 | PRD 用户任务 |
| 与菜单、排队工具或普通推荐有什么差异？ | 食序输出完整餐次，售罄会重算。授权需求能支持人工备餐，备餐又影响下一窗口推荐。 | PPT 第 3–6 页 |
| 你们的 AI 在哪里？ | 当前用可解释、可复现的规则型多目标决策与动态重规划。开发有 AI 辅助。运行不需要在线大模型。MCP 让授权宿主调用决策和运营能力。 | R01–R06、接口规范 |
| 学生一定要按推荐吃吗？ | 学生可调条件、拒绝、选备选或坚持可行偏好。售罄后旧意向保留，重规划不自动写新选择。 | C 端、E01 |
| 推荐如何选出首选？ | 先过供给、营业、预算、期限和食材等硬约束，再对剩余餐次评分。近似等优候选按排队等规则选首位。 | PRD §4，DECISION_ENGINE_SPEC.md |
| 匹配高代表数据好？ | 页面分开显示匹配程度和事实可信度，关键事实的缺失或过期会降低可信度，必要时阻断可选。 | R01、R06 |
| 六份需求从哪来？ | P/I/A 为四、六、三。对可见的项取 I、A、P 除以二向下取整里的最大值，所以为六，三个渠道独立。 | SIMULATION_SPEC.md，E01 |
| 为什么只加三份？ | 需求代理为六、W2 原计划为零，缺口六。菜品剩余配额、食堂产能、原料和缺口共同限制追加，示例原料仅支持三份。 | 历史提案截图，E01 |
| 点击批准后为何库存没变？ | 确认先预留资源并写确认审计。到目标供餐窗才生效、更新库存及发布快照。 | B 端计划与审计 |
| 如何证明有用的是确认动作？ | 对照用相同的预置场景。确认路径 W2 有三份烤鸭，不确认路径零份。两者的 C 端首选也不同。 | REPRODUCTION_LOG.txt，E01 两分支 |
| “今天吃了”来自刷卡吗？ | 来自用户自报。浏览、明确意向和自报分开记。当前没有真实刷卡或食堂交易接入。 | C 端我的午餐，数据契约 |
| 运营端能看个人记录吗？ | OPS 只能查询授权场所的固定时间窗聚合。达不到三个授权会话的渠道被屏蔽，撤回排除旧贡献。 | 授权与撤回日志 |
| 过敏信息缺失怎么处理？ | 用户明确给出限制后，缺证据就阻断相关候选。系统提示依据与不确定性，无法代替现场核对。 | R01 |
| 会不会重复确认或跨窗误操作？ | 验证角色、运行、快照和状态。幂等键防止重复副作用，过期或版本冲突需要重新核对。 | 运营接口与审计 |
| MCP 是否已经全部验收？ | 七项 MCP 工具经协议及程序验证。可见 Edge 人工回执的 GATE 1 仍待取证。现场网页 OPS 确认走 HTTP。 | M4 报告，PPT 第 9 页 |
| 为什么没用真实食堂数据？ | 赛期先实现可控、有对照的模拟闭环。真实接入需校方授权、数据时效和业务规则核验。 | SIMULATION 标识，PRD |
| 现在有多少人用、能降多少浪费？ | 目前没有真实用户规模和经营效果数据。105/105 是历史自动化验收数，3 份来自模拟场景。 | M4 报告，独立复验日志 |
| 怎样做下一步试点？ | 先接一个获授权场所的一段午餐窗口，监测供应数据的准确性，再对照学生选择耗时和备餐建议采纳。 | PPT 第 8 页、PRD §5 |
